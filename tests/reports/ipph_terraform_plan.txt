3. infra/datalake — ZERO DIFF (verified, not asserted)
--------------------------------------------------------------------------------

The hard constraint is that this feature must not touch infra/datalake at all,
because `aws_iam_policy.description` is immutable in AWS: editing it forces a
destroy-and-recreate of the writer policy and its role attachment, opening a
window in which cs-server holds no PutObject — and a data-lake flush in that
window is DROPPED, not retried.

$ git status --porcelain infra/datalake
(no output)

$ git diff HEAD -- infra/datalake | wc -l
0

$ git status --porcelain infra/
?? infra/media/

So the ONLY change under infra/ is the new, untracked infra/media/ directory.
No file under infra/datalake was read-modified, and no resource in it is
addressable from this module:

  - Separate state key: media/terraform.tfstate (backend.tf) vs
    datalake/terraform.tfstate. A `media` plan physically cannot enumerate,
    let alone propose a change to, a datalake resource.
  - Separate bucket: vibesense-media-<account_id>, not
    vibesense-datalake-<account_id>.
  - A NEW, separately-named IAM policy: `vibesense-media-profile-photo-writer`.
    It does not extend, rename, or re-describe `vibesense-datalake-writer`.
  - The only interaction with the shared cs-server EC2 role is an
    `aws_iam_role_policy_attachment` (and only when `cs_server_role_name` is
    set; default "" creates no attachment at all). Attaching a policy does not
    modify the role or any other policy already attached to it.

5. Apply ordering (why this matters operationally)
--------------------------------------------------------------------------------

A write outside the IAM policy fails AFTER the Apify scrape has already been
paid for. `instagram_profile_photo_enabled` therefore ships FALSE, and the
apply is verified before the job is ever enabled in prod. See
infra/media/README.md for the post-apply verification commands (bucket is not
publicly readable; an object IS readable through CloudFront carrying
`cache-control: public, max-age=31536000, immutable`).
